Overview & Problem Statement

Small businesses, charities, and finance teams process hundreds of supplier invoices each month across PDFs, scans, and receipts. Traditional accounts payable suffers from manual data re-entry, silent duplicate payments, undetected PO discrepancies, and unverified math errors. High-cost cloud extraction SaaS introduces vendor lock-in and monthly token fees.

InvoiceOps solves this with a 100% local-first, zero-cloud-cost platform. It pairs deterministic PDF text extraction with automated mathematical consistency checks, two-way purchase order verification, and a strictly auditable state machine ensuring human reviewers retain final financial authority.

Key Engineering Decisions

  • Assistive Automation, Not Black-Box Decisions: An invoice is never auto-approved by OCR or AI alone. Every field is annotated with confidence scores (HIGH, MEDIUM, LOW, UNVERIFIED) and human reviewers verify discrepancies.
  • Formula Injection Mitigation (CWE-1236): CSV exports sanitize spreadsheet formula triggers (=, +, -, @) to prevent remote formula execution attacks when finance teams open export sheets in Excel.
  • Strict Multi-Currency Separation: Invoices in GBP, USD, and EUR are aggregated strictly within their ISO currency codes without arbitrary currency blending.
  • Zero-Cost Local Architecture: Full operational capacity with zero external API fees, runs entirely on local Docker containers or local JVM with H2 database support.

Philosophy

Engineering Invariants, Not Assumptions.

Software engineering philosophy and distributed systems architecture.

True software reliability begins by defining and enforcing system invariants from day one. In high-throughput distributed backends and low-latency engines, relying on loose runtime assumptions leads to silent state corruption, unhandled race conditions, and cascading service outages. By codifying strict schema boundaries, static and runtime invariants, and defensive validation, software stays provably correct even under degraded network states.

Modern backends handle thousands of concurrent transactions across multi-core processors. Fast code is useless if it is not thread-safe. Through disciplined memory management, cache locality, and atomic concurrency primitives (in Java Virtual Threads, Spring Boot, C++ RAII, and Redis distributed locks), systems can process high-volume workloads with deterministic memory bounds and predictable sub-10ms P99 latency.

Network boundaries and external microservices are inherently volatile. Retries, transient timeouts, and packet jitter are standard operational reality, not edge cases. Every critical endpoint must be designed idempotently, accompanied by structured metrics, distributed tracing, and clear runbooks so systems can be understood, operated, and recovered with zero data loss.
